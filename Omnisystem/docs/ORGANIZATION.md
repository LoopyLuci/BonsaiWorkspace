# Documentation Organization Guide

## Structure Overview

This documentation is organized into 9 main categories for easy navigation:

### 1. Getting Started
Entry point for new users with installation and setup guides.

### 2. Quick Guides  
Essential how-to guides for common tasks and workflows.

### 3. Architecture
System design, component architecture, and design patterns.

### 4. Languages
Comprehensive documentation for all 7 Omnisystem languages:
- TITAN (systems programming)
- VERA (UI & components)
- HELIX (graphics & GPU)
- AETHER (async & distributed)
- AXIOM (formal verification)
- SYLVA (machine learning)
- NEXUS (responsive design)

### 5. Core Systems
Documentation for the compiler, runtime, and frameworks.

**Compiler/** - Complete compilation pipeline documentation
**Runtime/** - Virtual machine and execution environment
**Frameworks/** - All frameworks and modules

### 6. APIs
Complete API reference documentation.

### 7. Deployment
Operations, infrastructure, CI/CD, and deployment guides.

### 8. Project Status
Completion reports, development phases, and progress tracking.

### 9. Development
Setup guides, contribution guidelines, and testing framework.

### 10. Reference
Technical reference, configuration, and asset documentation.

## Navigation

Every section has an **INDEX.md** file providing local navigation and overview.

The main **README.md** provides global navigation and quick links.

## File Organization Principles

- **Clarity**: Files are named clearly and organized logically
- **Discoverability**: Multiple index files help users find information
- **Completeness**: 653 active documentation files covering all systems
- **Maintainability**: Clear structure makes updates easy
- **Accessibility**: Multiple entry points for different user types

## Archive

Legacy documentation and old folder structures are preserved in **_Archive/** for historical reference.

## For Contributors

When adding new documentation:
1. Place files in the appropriate section folder
2. Update the section's INDEX.md if needed
3. Add a link in the main README.md if it's a significant document
4. Keep filenames clear and descriptive
